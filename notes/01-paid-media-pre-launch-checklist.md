# 01 · Pre-launch checklist (paid media)

The twelve checks I run before a campaign is allowed to spend. Nothing here is clever —
each item exists because I have watched it go wrong on a real account.

## Account & structure

- [ ] **One objective per campaign.** Mixing lead-gen and purchases in one campaign makes both unreadable.
- [ ] **Naming convention applied** — `platform_objective_country_audience_creative_date`. If you cannot filter by name, you will export by hand forever.
- [ ] **Budget maths done at the ad-set level**, not just at campaign level. Platforms spend per ad set, not per average.
- [ ] **Geographic targeting double-checked** — especially “people interested in” vs “people located in”. The first one buys tourists.

## Tracking

- [ ] **Conversion event fires** — tested with a real click, in a real browser, not with the platform's “test event” button alone.
- [ ] **One primary conversion per campaign.** Secondary events are for reporting, not bidding.
- [ ] **Deduplication set** where the platform supports it (pixel + API double-counting is the most common silent inflator).
- [ ] **Attribution window written down** — 7-day click / 1-day view is not the same number as 1-day click, and the difference shows up in the first weekly report.

## Creative & landing

- [ ] **At least 3 creative variants** per ad set, with one clear variable between them.
- [ ] **Message match**: the headline of the landing page repeats the promise of the ad.
- [ ] **Landing page loads under 3s on 4G** — test it on a phone on mobile data, not on office wifi.
- [ ] **Form / checkout tested end to end**, including the “thank you” state that triggers the event.

## Before you press publish

- [ ] **A target cost per result exists** — a number, agreed with whoever owns the budget.
- [ ] **A stop rule exists** — e.g. pause any ad set above 1.5× target CPA after 50 clicks.
- [ ] **The dashboard is ready before the campaign is.** If reporting is built after launch, week one is guesswork.
